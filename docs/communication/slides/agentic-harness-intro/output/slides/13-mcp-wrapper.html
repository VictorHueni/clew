Tools · Under the hood

Most of MCP is a wrapper that makes CLI & API tools discoverable.

Peel back a typical MCP server and you find a shell command or an HTTP call it already had. What MCP adds on top isn't capability, it's a self-describing, standardized way for the agent to find and call it.

A thin translation shim: same command, wrapped in a schema.
What it adds — discoverability
Self-description. tools/list hands back names + typed schemas, so the agent calls a tool it has never seen.
Standardization. One protocol, reusable across every client, plus auth and a common error shape.
What it doesn't — the capability
The CLI or API still does the work. A bare gh or curl does the same thing, with no schema to load.
So the question is rarely “CLI or MCP?” but “does the agent need to discover this tool at runtime?” If it already knows the command, the CLI is enough; MCP earns its context cost when cross-client discoverability does.
