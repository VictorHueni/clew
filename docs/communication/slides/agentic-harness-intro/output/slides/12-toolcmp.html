Tools · Three ways in

CLI, MCP, API: three ways to give an agent hands.

Same goal: let the model act on the world. Different cost, different sweet spot.

CLI
shell + filesystem, via a Bash tool
Composable & pipeable; mature tools the model already knows (git, docker, kubectl); token-cheap; deterministic
Tool must be installed; output is unstructured text; no built-in discovery
The inner build / test / commit loop on local code.
MCP
a standardized server protocol
Discoverable & reusable across many clients; wire once, every app uses it; built for third-party integrations
Tool defs loaded upfront → context bloat; too many tools hurts accuracy; new security surface
Standardized access to external / third-party systems.
API
a direct HTTP / REST / SDK call
Full control; best latency & throughput; exact, bespoke fit for the integration
Bespoke wiring per service (the N×M tax); you own auth, retries, maintenance; no shared standard
Hot paths where control and speed matter.
No column wins outright; each pays off in a different place. That is the whole point of the next slide.
