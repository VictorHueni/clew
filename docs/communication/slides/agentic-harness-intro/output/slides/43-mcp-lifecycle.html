Appendix · MCP protocol lifecycle

One JSON-RPC session: negotiate, operate, notify.

Over stdio or HTTP. Capabilities are negotiated once at initialize; then it's discovery, use, and change notifications, until the transport closes.

Capability negotiation · once, at initialize
Client declaresrootssamplingelicitation
Server declarestoolsresourcespromptslogging
Sub-caps gate the extras: listChanged (tools · resources · prompts) and subscribe (resources only). Both sides use only what was negotiated.
Kept live by notifications · server → client
notifications/resources/updated → the client re-reads that resource.
…/list_changed → the client re-lists tools, resources or prompts.
No polling: the session stays in sync as the server's surface changes.
